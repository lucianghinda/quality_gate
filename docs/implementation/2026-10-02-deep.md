# Optional deep analysis implementation plan

Date: October 2, 2026. Base: `76b0de7772ba123193f279bb3f35e5e0cb4983f3`.
Worktree: `.worktrees/deep`; branch: `codex/deep`. Doctor PR #8 remains independent.

**Goal:** make the roadmap's on-demand maintainability pass available through `quality_gate deep`, starting with optional RubyCritic.

**Architecture:** extend the existing gate configuration, registry, runner, and reporters. A RubyCritic adapter uses the existing subprocess timeout/failure boundary and reads RubyCritic's JSON file from a unique temporary directory. Normalize reported smells into existing findings; do not introduce score policy or new reporting schemas.

**Tech stack:** Ruby >= 3.2, standard-library JSON/tmpdir, existing QualityGate abstractions, optional user-provided RubyCritic 5 CLI. No gem dependencies, new suppressions, or coverage budget changes.

## Decision and limits

The roadmap's next Phase 2 engineering item is deep analysis. Baseline/ratchet awaits brownfield adoption evidence; Codex hook automation requires a separate runtime capability review. The user authorized a new worktree, implementation, and subagents; Luna authors and independent reviewers perform bounded tasks while the leader owns integration and delivery.

RubyCritic adds Flog complexity and Flay duplication observations, while also including Reek. Its JSON does not identify the originating analyzer, so report all emitted smells without guessing attribution or suppressing overlap. Deep complements verify; it is neither a substitute for tests/security checks nor an automatic edit/session gate. Debride is a separate follow-up.

Rejected alternatives: a project-score-only result would invent an unreviewed budget; adding analyzer dependencies would expand every installation; an empty default adapter list would report clean without doing work; parsing human stdout would discard the supported JSON contract.

## Command and configuration contract

`quality_gate deep` is a normal gate with text/JSON/Markdown and existing exit semantics: 0 means analysis completed with no findings, 1 means reported smells, 2 means invalid input/configuration or tool failure. Help must work without configuration/analyzer availability.

Add `deep` to allowed adapter/command layers, default `adapters.deep: [rubycritic]`, default `commands.deep: {}`, and CLI gate/help/registry tables. Preserve every existing gate's defaults. RubyCritic is optional: absence is an actionable tool failure, never an empty clean result. Keep the generator's fully commented defaults snapshot current; its existing regression must still prove that the generated file is inert. Do not change generated hooks, active init configuration, CI workflows, Gemfile, or gemspec dependencies.

First slice is **project-wide**: invoke RubyCritic on `.` regardless of configured/CLI-selected files, like existing project-scoped audit tools. Record `scope: project` and no requested_files in runner metadata. CLI still validates selected paths as usual; documentation/help explicitly say RubyCritic scans the project. Selected-file support is outside this slice.

Use the configurable launcher `commands.deep.rubycritic` (argv prefix), default `["rubycritic"]`. Append adapter-owned `--format json --no-browser --minimum-score 0 --path <temporary directory> .`; never invoke a shell. The appended flags control output and avoid RubyCritic's host/default minimum score. Reuse configured `timeouts.rubycritic` or the existing default timeout. Deep writes only temporary analyzer artifacts and cleans them on success/failure; it does not keep HTML or project `tmp/rubycritic` reports.

RubyCritic 5 emits stdout score text and writes `<path>/report.json`. Accept only normal process exit 0 after forcing minimum score 0; nonzero/signaled/missing process status is a tool failure even if a JSON artifact exists. A fresh directory per call prevents accepting an old report. Missing/unreadable/malformed report or invalid shape is a tool failure; retain safe stderr context through the existing failure renderer. No new filesystem security abstraction is needed for the adapter-owned fresh temporary directory.

## JSON and findings contract

Validate the root object, `metadata.rubycritic.version` (nonempty String), finite Numeric `score` within 0..100, and a nonempty `analysed_modules` array. RubyCritic emits score 0 for no modules; fail explicitly with 'no Ruby modules analyzed' rather than implying a clean project. Do not enforce a score threshold.

Each module must be an object with nonempty String `path` and array `smells`. Each smell must be an object with nonempty String `type`, String `context`/`message`, and nonempty array `locations`. Each serialized location is an object with nonempty String `path` and Integer `line` >= 0. Ignore upstream metadata not used in the findings contract; never coerce invalid fields into valid ones.

Emit one warning Finding per location: `tool: rubycritic`, `rule: type`, `file: path`, `line: line`, `message: "<context> <message>"` (strip outer spaces). Multi-location duplication stays actionable in each reported file. Coalesce exactly identical normalized findings across modules: real Flay reports the same multi-location smell under each affected module, and repeating the same finding adds no information. No smells across valid analyzed modules means clean. Any malformed module/smell/location fails the whole report, without silently dropping entries. Use the existing ParseError and safe failure finding boundary.
