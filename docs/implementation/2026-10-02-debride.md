## Decision and limits

Debride is the separate follow-up selected in the deep-analysis plan. It contributes possible unreferenced methods rather than another complexity score. These are review candidates: dynamic dispatch, external consumers, Rails callbacks, and metaprogramming can produce false positives. No automatic deletion or proof of dead code is implied.

Register Debride but preserve `adapters.deep: [rubycritic]` and every existing default. Users enable `adapters.deep: [debride]` or `[rubycritic, debride]`. Keep init profiles, commented defaults, hooks, generated workflows, Gemfile, and gemspec dependencies unchanged. Installation and use remain optional and manual. The feature is unreleased.

The user authorized a new isolated worktree, Luna subagents, documentation before code, and a separate PR. The leader integrates and verifies; authors have bounded write ownership and do not commit independently. Deliver one atomic Lore commit.

Rejected alternatives: adding Debride to the default would require a second analyzer for existing users; parsing human text would lose the supported JSON contract; matching selected diagnostic strings would miss other upstream skip/error paths; a new shared subprocess/report framework would exceed this adapter's needs.

## Command and report contract

Default command is `debride --json .`. `commands.deep.debride` supplies a launcher argv prefix; append `--json` and `.` without a shell. Reuse `timeouts.debride` or the existing default. The scan is project-wide even with valid `--files`; runner metadata is `scope: project`, `requested_files: []`. Existing CLI path validation still applies.

Debride's CLI normally exits 0 for both clean reports and candidates, but catches parse/processing errors and emits diagnostics while continuing. Require a normal exit 0 and whitespace-only stderr. Any diagnostic, malformed/empty JSON, missing executable, timeout, missing/signaled/nonzero status, or malformed report entry becomes a tool failure. Returned-output/schema/status failures use ParseError so the existing renderer retains captured stderr safely; spawn/timeout failures retain the existing exception message (capture does not expose partial timeout stderr). In particular, valid JSON plus a skipped-file warning cannot become clean. Verbose/custom-launcher chatter is consequently unsupported. No temporary report files are needed.

Expected JSON is an object with a required `missing` object mapping class/scope names to arrays of `[name, location]` pairs. An empty `missing` object is clean. Ignore unused upstream metadata such as optional `focus`. Validate every pair and location; do not silently drop malformed candidates or coerce fields. Class/scope and candidate names must be nonempty strings. Real Debride 1.15.2 reports top-level methods/constants under `main`, and class/module members under their named scope. Locations use a final numeric line or line range after a colon; preserve colon/spaces in paths, require a nonempty path and positive ordered lines, and normalize the first line.

Emit one existing warning Finding per candidate with `tool: debride`, `rule: potentially_unused_method`, upstream file and first line, and a message naming the scope and candidate as potentially unused. Static analysis does not reliably distinguish every method/constant kind: avoid inventing an instance/class-method separator. Zero findings exits 0, candidates exit 1, tool failures exit 2. Debride exposes no analyzed-file count; an empty report is not a guarantee that Ruby files were present or all dynamic references were understood. Do not invent an independent project crawler.

## Upstream probe evidence

Official Debride 1.15.2 was downloaded and extracted into `/private/tmp` without installation. Its CLI ran using already installed runtime dependencies. Clean input emitted `{"missing":{}}` with exit 0 and empty stderr. Regular methods emitted `path:START-END`, including one-line `START-START`; constants emitted `path:START`. Top-level candidates used `main`; class/module candidates used their names. Invalid-only input emitted the same empty JSON and exit 0, with a parse-error skip diagnostic on stderr. Mixed valid/invalid input retained candidate JSON and emitted that diagnostic. JSON ignored `--minimum 99`. These observations establish the strict stderr policy and range parser before implementation.

Independent Luna plan review approved the minimal scope after clarifying captured-stderr versus timeout behavior and replacing the contingent scope encoding with this observed contract.
