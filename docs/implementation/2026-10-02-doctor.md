# QualityGate Doctor Implementation Plan

> For implementation agents: use Ruby test-driven-development and subagent-driven-development. Luna implementers own bounded files; the leader orchestrates integration, independent specification review, Ruby simplicity review, and final verification.

**Goal:** make observed setup friction actionable through a read-only `quality_gate doctor` command.

**Architecture:** a small Doctor coordinator assembles named checks from configuration, launcher, comparison, coverage-evidence, and hook-history probes. A Doctor-specific report uses existing field sanitization and keeps readiness separate from Runner findings and the gate reporters. The CLI passes its existing adapter registry; no second registry or plugin framework is introduced.

**Tech stack:** Ruby >= 3.2, standard library, existing Config/HookLog/Undercover process boundaries. No dependencies, default-gate changes, version bump, publication, or automatic repair.

**Base:** planning began on merged main `8af0893de378cfd8076392d39b874f44987d818c`; delivery incorporates release-preparation PR #7 at `76b0de7772ba123193f279bb3f35e5e0cb4983f3`. Branch `codex/doctor` is in an isolated worktree. The user authorized implementing the selected next feature. The leader presented the read-only contract; independent Luna architecture review accepted the Doctor-specific report over changing gate semantics.

## Public command and result contract

```sh
bundle exec quality_gate doctor
bundle exec quality_gate doctor --format json
bundle exec quality_gate doctor --help
```

Doctor supports text and JSON; text is its default, independent of the configured gate format. Reject Markdown, positional arguments, `--files`, and unknown options with exit 2. Help works without loading project configuration. Never append a gate hook-health warning to Doctor JSON stderr.

Each check has three String fields: `id`, `status`, and `message`. The message states the bounded observation and a next action when non-ready. Status is one of `ready`, `warning`, `blocked`, `unchecked`, or `not_applicable`. The JSON envelope is:

```json
{
  "scope": "preflight",
  "checks": [{"id": "configuration", "status": "ready", "message": "Configuration loaded; application checks were not run."}],
  "summary": {"ready": 1, "warning": 0, "blocked": 0, "unchecked": 0, "not_applicable": 0}
}
```

Text prints the same checks/statuses/messages and a counted preflight summary. A small `Reporters::Doctor` renderer uses existing FieldSanitizer within its owning namespace; keep that private sanitizer private. DoctorReport owns checks, summary, and exit reduction. No user-controlled exception text may escape unhandled or produce terminal control sequences.

- Exit 0: all applicable preflight checks are ready; not_applicable is neutral. This is not a clean gate or verified application boot.
- Exit 1: no blocker, but a warning or unchecked observation remains.
- Exit 2: any blocker, invalid input, report-write failure, or unexpected Doctor failure.
- A malformed configuration produces a named blocked configuration check and explicitly unchecked configured checks, without starting downstream probes. Unknown configuration keys are warnings rather than a second validation policy.

## Check boundaries

### Runtime and configuration

Report current `RUBY_VERSION`, `RbConfig.ruby`, and loaded Bundler version/context without running `bundle check`, requiring the application, or installing anything. An unbundled invocation is unchecked; a successfully loaded bundle is not proof that every command works. Doctor cannot diagnose a bundle that prevents the CLI itself from loading; README must provide an external Ruby/Bundler troubleshooting path.

Reuse `Config.load` (`lib/quality_gate/config.rb:45`) and its defaults/validation. Use the existing CLI registry (`lib/quality_gate/cli.rb:225`) through injection. Every configured adapter occurrence has `command.<gate>.<adapter>` status; an unknown adapter is blocked. Validate executing adapters' timeout/argv through their existing methods. SimpleCov is an internal file reader and needs configured line or branch coverage thresholds, matching the current CLI contract. An intentionally empty gate adapter list has a named not_applicable check rather than disappearing.

### Launcher availability

Inspect executable files and PATH only; never execute the configured command or analyzer. Known direct analyzers and test launchers are checked for executable existence. Undercover's launcher is checked separately from comparison resolution; do not call its command method just to discover a launcher and trigger unbudgeted Git work.

Resolve all explicit relative launcher/script paths and relative/empty PATH entries against the supplied project `dir`, never the caller's working directory. Known adapter command methods may be used only to extract safe launcher argv with `files: []`; their cwd-sensitive RuboCop/Reek configuration flags are not assessed or advertised as verified. Undercover uses its separate budgeted resolver. Include an unrelated-cwd fixture for direct scripts, bundle/Ruby targets, and PATH lookup; assert `Dir.pwd` is unchanged. An absent PATH with an ambiguous OS default lookup is unchecked rather than a guessed missing-tool blocker.

Support direct known launchers, `bundle exec <launcher>`, and simple `ruby <script>` / `ruby -S <launcher>` forms. Validate outer launchers and explicit target files. Ruby scripts need to be readable regular files, not executable. A nested bare target missing from the current PATH is unchecked rather than definitely absent from a bundle. Arbitrary custom wrappers, Ruby evaluation/options, and unrecognized launcher forms remain unchecked even when their outer executable exists. Missing explicit files or direct executable launchers are blockers. Report exactly what was checked; do not assert tasks, framework initialization, tool versions, dependency compatibility, or wrapped commands were verified.

Ignore configured tools that are disabled in adapter lists. Do not invent another command override policy: retrieve the actual adapter command where safe, plus the established TestSuite/Herb overrides. A found executable is only launch-path evidence.

### Git comparison

When Undercover is enabled, reuse its comparison resolver in a small DoctorGit subclass. Override Git argv to include `-C <project dir>`; do not change global working directories. Use inherited process capture/cleanup and one five-second deadline across all Git calls, including explicit-ref validation. Clear the budget in ensure.

Validate explicit comparison points resolve to commits; reject option-like leading `-` refs before a Git call. An invalid explicit ref is blocked. An unavailable automatic comparison, a non-repository, or a timed-out probe is unchecked with an actionable history/comparison explanation. Missing Git executable is blocked. No network/fetch operation is allowed. When Undercover is disabled, comparison is not_applicable.

### Coverage evidence

Inspect only artifacts required by enabled adapters: Undercover's `coverage/coverage.json` and SimpleCov's `coverage/.last_run.json`. No relevant adapters means not_applicable. Missing artifacts before the initial suite are unchecked with an instruction to run verify; never diagnose absent wiring from missing output alone.

Read at most 1 MiB per artifact, regular files only, with nonblocking/no-follow opening where supported and identity validation. Symlinks, special files, unreadable/oversized artifacts are unchecked. Malformed JSON or unusable expected top-level shape is a warning. Undercover evidence checks the formatter's `meta`/`coverage` mapping; SimpleCov checks finite 0..100 line percentage and a branch percentage when that budget is configured. Ready means readable structured evidence only; freshness, detailed engine validity, wiring, and budget compliance remain unverified. Never delete, update, collate, or regenerate coverage.

### Hook history

Use `HookLog.recent(limit: 20)` (`lib/quality_gate/hook_log.rb:7`), which bounds tail reads and ignores malformed records. Report recent unavailable/verify_unavailable records as warnings with guidance to inspect the bundle/hook setup. Valid history without such records is ready only for that historical observation, not current hook installation.

No history and no installed QualityGate hook files is not_applicable (automatic feedback is not verified). Installed hooks without readable valid history, and existing empty/corrupt/unsafe/unreadable logs, are unchecked. Do not call zero valid records healthy. No hooks or logs are written.

## Decisions and remaining risks

Rejected changing Runner/gate reporters: preflight status and gate findings have different meanings; the existing reporting schema stays compatible. Rejected a generic diagnostics/plugin framework: named checks and existing registry are sufficient. Rejected executing launchers or booting applications: Doctor must not turn a diagnostic request into a suite/analyzer/install run.

Static readiness cannot establish production compatibility or sustained adoption. Git capture is bounded; ordinary filesystem I/O still depends on the OS. Coverage artifacts can predate source edits; always describe evidence limits and direct users to enforced verify. Hook history is advisory, not current enforcement proof. Two optional latency benchmarks and the two-app sustained-use milestone remain separate evidence work.

Independent Luna specification review approved the final contract. Separate Ruby simplicity review found no blocking issues; the author removed unused path helpers, one-use forwarding layers, duplicate inner target checks, and an unreachable CLI require guard. Shared path lookup handles launchers and Git; internal readers remain private. No dependencies, suppressions, or budget relaxations were added.

The bounded-file growth regression first demonstrated a one-byte over-read and now proves the exact 1 MiB limit with post-read size/identity validation. Launcher regressions distinguish missing explicit targets from unresolved bundle targets, including absent PATH. Error-path regressions keep output failures at exit 2 and sanitize unsafe messages.

Doctor uses standard OptionParser parsing, consistent with the existing CLI. A Ruby 3.2 regression verifies that `--format=json` reaches Doctor and that unsafe exception messages still produce the bounded JSON failure report. The optional exact-match mode was removed because Ruby 3.2 rejects that supported spelling while Ruby 4 accepts it; unknown-option rejection remains covered.

The two opt-in named-machine latency tests remain skipped in ordinary verification. Application boot, gate execution by Doctor, tool compatibility, fresh coverage wiring, and sustained two-app adoption are outside this static preflight evidence.
